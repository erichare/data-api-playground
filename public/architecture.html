Data API Playground

Architecture overview — Next.js 16 · Astra DB · watsonx.ai

🔍 /api/chat — RAG Pipeline  ·  each step streams two events: running → complete
STEP 1
Analyze
Reads query + collection schema. Outputs structured plan: target collection, search mode, intent, limit, sort field.
ibm/granite-3-8b-instruct
STEP 2
Embed
Generates a 768-dim query vector. Skipped for server-side vectorize collections.
watsonx AI SDK · IBM Granite Embedding 125M
STEP 3
Search
Queries Astra DB using the chosen mode: $vector, $vectorize, $hybrid, or lexical sort.
Astra DB — Data API
STEP 4
Respond
Synthesizes a natural language answer grounded in the retrieved documents.
ibm/granite-3-8b-instruct

☁️ External Services
Astra DB — DataStax Data API
Schemaless document store with first-class vector support. Supports client-side vectors ($vector), server-side vectorization ($vectorize), hybrid, and lexical search. Also stores conversation history in dedicated collections.
astra-db-ts SDK
watsonx.ai — IBM
Hosts ibm/granite-3-8b-instruct (LLM) and ibm/slate-125m-english-rtrvr-v2 (embeddings). Used for all four pipeline steps: analyze, embed, search (via Astra), and respond.
watsonx-ai SDK
HuggingFace Inference API
Fallback embedding provider when watsonx is not configured. Uses IBM Granite Embedding 125M via router.huggingface.co. Skipped when the target collection uses server-side $vectorize.
REST · fallback

💬 Conversation History — Astra DB Collections new
dap_conversations
_id string UUID
name string user-editable display name
createdAt string ISO timestamp
updatedAt string updated on every new message
messageCount number denormalized for sidebar display
activeCollection string last queried DB collection
dap_messages
_id string UUID
conversationId string → dap_conversations._id
role string "user" | "assistant"
content string message text
timestamp string ISO — sort key for ordering
searchMode string optional · assistant only
pipelineSteps object[] optional · full trace
sources object[] optional · retrieved docs
No vector fields needed — accessed by exact ID lookup and sorted by timestamp. Created automatically on first use. No schema migration required. No auth system — the Astra token scopes all access.
